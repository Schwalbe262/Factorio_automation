# 유한 초기 연구의 중간재 회수 복구

`BootstrapLogistics`의 비물류 연구 대상은 원래 원료 예산과 기계·입력 포트·월드·카탈로그·계획·생산 기준값을 유지합니다. 기존 건설 수집기가 연구 전용 기어 출력을 가져간 경우, 성공한 실제 `take_many` 영수증으로 입증한 수량만 정상 원료로 보충할 수 있습니다. 원래 `required_inputs`와 연구 이력은 수정하지 않습니다.

`prepare_diversion_recovery(obs)`는 읽기 전용 제안 API입니다. 같은 월드 `jobs.json`의 유일한 해당 연구 작업과, 고정 입력 포트로 실제 이동한 최초 원료 투입 영수증을 찾습니다. `job-events.jsonl`을 스트리밍하며 그 이후의 동일 기어 기계 출력에 대한 정확한 의도/결과 쌍을 검사합니다. 각 쌍은 작업 키·월드·유닛·이름·위치·출력 종류·실제 수량 보존을 확인하고 원본 두 줄의 SHA256으로 식별합니다. 기계에 수동으로 없는 수량을 추정하거나 연구 완성품·실험실의 의도된 회수를 보상하지 않습니다. 로그·세계·유닛이 불명확하거나 관련 미해결 행동이 있으면 보충을 승인하지 않습니다.

실제 `step`은 원래 원료가 모두 투입됐고, 기어/철 공급 재고가 없으며, 새 과학 생산이 미완료이고, 전력 있는 기계·연구 소비 계수가 1,800 게임 틱 동안 정체했을 때만 복구 세대를 추가합니다. 기계 생산이나 연구 소비가 진행되면 정체 관찰을 새로 시작합니다. 각 세대는 기존 기준값에 결합한 불변 승인 해시·영수증 목록·카탈로그에서 계산한 보충 원료·실제 투입 수량을 별도로 보존합니다. 모든 세대의 기어 보상 총합은 원래 유한 배치의 기어 요구량을 넘지 못합니다.

예를 들어 정상 제조 기어 6개가 실제로 회수됐고 설치 카탈로그가 기어당 철판 2개이면, 추가 허용량은 철판 12개입니다. 원래 철판 50개/구리판 25개는 그대로이고 유효 허용량은 62개/25개입니다. 부족 원료는 기존 일반 수집기로 마련하고, 기존 철 입력 상자에 일반 `insert`로 지불합니다. `repair_fund` 의도와 복구 ID를 먼저 저장하고 실제 `moved`만 기록합니다. 부분 이동은 남은 양만 재시도하며 불명확한 영수증은 의도를 유지해 명시적 조정 전까지 중단합니다. 재시작·중복 로그는 새 예산을 만들지 않습니다.

완료 증명은 기존과 같이 정상 연구 완료, 같은 기계에서 이번 대상 기준값 이후 필요한 과학 팩 생산, 기준값 이후 양수인 실제 연구 소비를 모두 요구합니다. 연구가 기준값 이전부터 진행 중인 경우도 유지합니다. 복구 입력·실제 투입량·영수증 해시를 증명에 포함합니다. 물자 생성, 연구/생산 계수 설정, 무한 원료 공급, 기존 체크포인트 초기화는 없습니다. 로그 감사는 최대 64MiB/20만 줄/줄당 1MiB로 제한하며 초과 시 명시적으로 차단합니다.

이 모듈의 개발 검증은 가짜 세계로 영수증 3+1+2개→철판 12개, 최초 투입 전 기록 제외, 다른 월드/유닛/위치, 미확정 결과, 중복·재시작·부분 이동, 실제 25개 생산/25개 소비 조건을 검사합니다. 실제 실행과 모든 게임 행동은 기존 단일 writer를 통해서만 수행합니다.

## 옛 물류 배치: 손실량 불명 상태의 유상 재조달

옛 `bootstrap-logistics.json`에는 실제 영수증 확인 전에 할당을 적는 구형 형식이 남아 있을 수 있습니다. 새 월드와 새 형식은 이제 다른 초기 연구와 같은 영수증 우선 엔진을 사용하므로 원료 투입 의도만으로 예산이 소진되지 않습니다. 기존 파일은 초기화하거나 새 형식으로 덮어쓰지 않습니다.

옛 배치는 원래 철판 투입 상자의 정상 유상 생성, 실제 40개 투입, 같은 위치의 다른 유닛 상자의 유상 생성 영수증을 원문 해시로 결합할 수 있을 때 한 번만 재조달할 수 있습니다. `reused` 생성, 미해결 행동, 불분명한 세계·수량·결과는 거부합니다. 과거 원료가 철판으로 남았는지, 기어가 됐는지, 파괴·유실됐는지는 **UNKNOWN**으로 보존합니다. 이를 40개가 확정 손실됐다는 증명이나 무상 환급으로 표현하지 않습니다.

`prepare_legacy_repurchase(obs)`는 읽기 전용 제안입니다. 실제 수락은 물류 연구가 0%, 셀의 철판·기어·과학 팩이 0개, 플레이어·모든 실험실에도 과학 팩이 0개, 셀의 정상 지불 구리판 20개가 보존되고 기계가 연결·전원 공급된 상태에서 1,800틱 정체했을 때만 가능합니다. 현재 월드·카탈로그·계획·기계·상자·실험실 유닛과 새 생산/소비 기준값을 고정합니다. 원래 40철/20구리 할당과 옛 기준값은 유지하며 `legacy_repurchase`에 별도 40철 정상 지불 허용량과 실제 `moved`만 적습니다. 이미 지불한 구리 20개는 재사용합니다.

새 과학 팩은 고정 출력 상자에서 실제 회수한 수량만 실험실에 공급합니다. 완료는 새 세대 기준값 이후 과학 팩 20개 생산과 20개 소비 및 자연 물류 연구 완료를 요구합니다. 기존 공용 기계의 누적 35회 생산은 새 배치의 증거가 아닙니다. 새 세대에서 다시 유닛이 바뀌거나 출처를 알 수 없으면 중단하며 두 번째 자동 재조달 예산은 만들지 않습니다.

개발 월드 읽기 전용 검증 tick713788: 옛 상자1099 → 실제40철 투입259102 → 새 상자1118 유상 생성259822, 현재 기어41/과학35, 전역 과학 생산45/소비45, 보존 구리20개를 확인했습니다. 새 허용량은 유상40철이며 과거 실제 손실량은 불명입니다. 검증은 제안만 수행했고 체크포인트 SHA는 바뀌지 않았습니다.

`starter_research`로 같은 대상을 선택해도 기존 기계 배치가 있으면 그 소유자의 실행·영수증·증명을 재사용합니다. 물류 작업은 공유 셀에 이미 비용을 지불한 현재 연구가 있으면 먼저 그 연구를 진행하고 영수증을 원래 소유자에게 전달합니다. 선행 연구의 완료 증명은 물류 작업의 완료로 인정하지 않습니다. 월드·카탈로그가 일치하는 등록 셀의 두 기계가 올바른 레시피로 연결되어 실제 양의 전력을 갖고 연구소도 작동 가능하면, 원격 석탄 공급원의 오래된 검사 때문에 지역 연구를 대기시키지 않습니다. 지역 전력이 없으면 기존 발전 복구 조건을 유지하며 발전 완료 플래그는 바꾸지 않습니다.
